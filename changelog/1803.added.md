Add `warp.geometry.sparse_marching_cubes`, which extracts an isosurface directly from an
implicit function (a batched Python callable `evaluate(points: wp.array(dtype=wp.vec3)) -> wp.array(dtype=wp.float32)`)
without building a dense grid, so cost scales with surface area rather than volume. Implement `evaluate` entirely
with Warp to keep the whole pipeline on the GPU, or wrap a NumPy/PyTorch field at the cost of a device/host sync per
call. Its grid is specified as `nx, ny, nz` node counts plus `lower`/`upper`,
matching `warp.geometry.IsoSurfaceMarchingCubes.extract`, so the two are interchangeable. The two stages are also
available separately: `warp.geometry.sparse_cells_via_lipschitz_pruning` selects the cells near the level set, and
`warp.geometry.sparse_marching_cubes_from_cells` extracts a mesh from an explicit list of cells and their sampled
corner values. See `warp/examples/geometry/example_sparse_marching_cubes.py`.

`warp.geometry.sparse_marching_cubes_from_cells` supports backward-mode automatic differentiation with respect to
`corner_values`, matching `warp.geometry.IsoSurfaceMarchingCubes.extract`'s existing support for `field`.
`warp.geometry.sparse_marching_cubes` inherits this w.r.t. the values its `field` callable returns, as a
side effect of reusing the same extraction core. `sparse_cells_via_lipschitz_pruning`'s cell selection is not
differentiated.
